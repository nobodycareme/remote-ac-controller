# 西电校园网自动认证

> **ESP8266 上电自动认证西安电子科技大学校园网** — 连接校园开放 SSID 后，自动完成 Wi-Fi 关联、DHCP 地址获取、Captive Portal 探测、Srun 认证和互联网连通性确认。

---

## 概述

本功能允许 ESP8266 NodeMCU 在上电后自动接入西电校园网（Srun 4000 认证系统），无需手动打开浏览器完成 Portal 认证。设备关联校园开放 SSID 后自动走完整认证流程，随后才继续连接 MQTT 云服务。

**功能默认关闭。** 仓库中提交的默认配置里，`ENABLE_CAMPUS_AUTH`、`ENABLE_AUTO_CAMPUS_AUTH`、`ENABLE_CONTROLLED_LIVE_AUTH` 全部为 `0`，全新克隆可直接编译且不会向任何门户发送请求。

## 工作原理

```
ESP8266 上电
  → 初始化 DHT11、红外模块、串口 CLI
  → 如果 ENABLE_WIFI=1：启动 Wi-Fi，关联校园 SSID
  → 获取 DHCP 地址
  → 如果 ENABLE_AUTO_CAMPUS_AUTH=1：执行 Captive Portal 探测
  → 如检测到 Portal：校验 TLS 指纹 → 执行 Srun 认证
  → 连续 3 轮验证互联网连通性（3/3 成功才判定 ONLINE）
  → 如果 ENABLE_CLOUD=1：启动 MQTT 和遥测
  → 持续监控 Wi-Fi、互联网和 MQTT 状态
```

## 支持的宏定义

| 宏 | 默认值 | 说明 |
|----|--------|------|
| `ENABLE_WIFI` | 1 | 控制 Wi-Fi 硬件和连接 |
| `ENABLE_CAMPUS_AUTH` | 0 | 编译 Captive Portal 探测与 Srun 认证代码 |
| `ENABLE_AUTO_CAMPUS_AUTH` | 0 | 上电是否自动执行 Portal 检测与认证 |
| `ENABLE_CONTROLLED_LIVE_AUTH` | 0 | 是否把 `campus_secrets.h` 中的真实凭据编入固件 |
| `ENABLE_CLOUD` | 0 | 控制 MQTT 和云连接 |
| `CAMPUS_PROFILE_HEADER` | 未定义 | 校园参数 Profile 头文件路径；`ENABLE_CAMPUS_AUTH=1` 时必填 |

开关的完整约束规则见 `firmware/shared/RemoteACCore/src/config/feature_gates.h`（单一权威来源）。若 `ENABLE_CAMPUS_AUTH=1` 却未选择 Profile，构建会直接 `#error` 终止——固件绝不会静默指向一个未指定的门户。

## 配置的三个层次

配置被刻意拆成三层，职责与保密级别互不混淆：

| 层 | 文件 | 是否入库 | 内容 |
|----|------|----------|------|
| 1. 功能开关 | `Remote_AC_Controller.ino.globals.h`（Arduino IDE）<br>`-D` 构建标志（PlatformIO） | 否（git-ignored） | 启用哪些功能、选哪个 Profile |
| 2. 校园公开参数 | `config/profiles/xidian.h` | 否（仅 `*.example.h` 入库） | SSID、门户主机、ac_id、TLS 指纹 |
| 3. 账号凭据 | `config/campus_secrets.h` | 否（git-ignored） | 学号、密码 |

第 2 层只含**公开非秘密**参数，第 3 层才是凭据。二者分离，是为了让第 2 层可以随仓库以 `*.example.h` 形式公开发布，而第 3 层永远不会离开你的磁盘。

## 配置步骤

### 1. 复制 Profile

```bash
cd firmware/shared/RemoteACCore/src/config/profiles
cp xidian.example.h xidian.h        # xidian.h 已被 git-ignore
```

`xidian.example.h` 中的参数均为公开信息，可直接使用，无需修改。

### 2. 启用校园网认证

**Arduino IDE**（官方 Global Build Options 工作流）：

```bash
cd firmware/arduino-ide/Remote_AC_Controller
cp Remote_AC_Controller.ino.globals.example.h Remote_AC_Controller.ino.globals.h
```

编辑 `Remote_AC_Controller.ino.globals.h`：

```cpp
#define ENABLE_WIFI                 1
#define ENABLE_CAMPUS_AUTH          1
#define ENABLE_AUTO_CAMPUS_AUTH     1
#define CAMPUS_PROFILE_HEADER       "profiles/xidian.h"
```

该文件由 ESP8266 核心的 `mkbuildoptglobals.py` 在预构建阶段自动 force-include 进**每一个**编译单元，你不需要在 `.ino` 中 `#include` 它，也不需要修改 `sketch.yaml`。详见 [Arduino IDE 使用指南](./Arduino-IDE使用指南.md)。

**PlatformIO**：通过 `tools/dev.ps1` 的 Profile 参数传入，不要手工调用 `pio`。

```powershell
./tools/dev.ps1 build -Profile local-campus-example
```

该 Profile 仅用于验证公开校园认证代码能够编译。它展开为 `-DENABLE_CAMPUS_AUTH=1 -DENABLE_AUTO_CAMPUS_AUTH=0 -DENABLE_CONTROLLED_LIVE_AUTH=0 -DCAMPUS_PROFILE_HEADER=\"profiles/xidian.example.h\"`：不读取真实校园账号密码，不会自动登录，也不能作为真实校园认证的烧录配置。真实认证请使用下方 Arduino IDE 的本地 globals 配置。注意 `-D` 字符串宏的双引号**必须转义**，否则 PlatformIO 会剥掉引号，导致 `#include expects "FILENAME" or <FILENAME>` 编译错误。

### 3. 西电校园网参数（公开非秘密）

下表取自 `config/profiles/xidian.example.h`：

| 参数 | 宏 | 值 | 说明 |
|------|----|----|------|
| Wi-Fi SSID | `CAMPUS_SSID` | `stu-xdwlan` | 校园开放 SSID，无 WPA 预共享密钥 |
| 门户主机 | `CAMPUS_PORTAL_HOST` | `w.xidian.edu.cn` | base_url 仅为 `https://w.xidian.edu.cn`，不含路径后缀 |
| ac_id | `CAMPUS_AC_ID` | `8` | 接入控制器编号 |
| 域后缀 | `CAMPUS_DOMAIN` | `""`（空） | **不要**追加 `@lt`/`@yd`/`@dx`，srun info 字段以空域构建 |
| 认证算法 | — | Srun 4000 | challenge-response + `srun_bx1` 编码 |

Srun 接口端点（所有 srun 校园网通用）：

```
challenge  GET   https://w.xidian.edu.cn/cgi-bin/get_challenge
login      POST  https://w.xidian.edu.cn/cgi-bin/srun_portal   (action=login)
logout     POST  https://w.xidian.edu.cn/cgi-bin/srun_portal   (action=logout)
```

`/index_8.html` **仅**用于只读门户探测（`INSECURE_PROBE_ONLY`），绝不在该路径上发送凭据。

### 4. TLS 叶证书指纹固定

ESP8266 只有约 80KB 可用 RAM，无法承载完整 CA 链校验，因此 BearSSL 采用**叶证书指纹固定**（`setFingerprint`）。指纹、签发者、有效期均为公开信息，随 Profile 一同发布：

| 字段 | 值 |
|------|----|
| SHA-1 指纹 | `F4:BD:59:32:8E:77:8C:CB:AD:6E:AE:85:86:59:36:FD:0D:28:47:F9` |
| 生效日期 | 2025-10-16 |
| **到期日期** | **2026-11-17** |
| 签发者 | GlobalSign RSA OV SSL CA 2018 |
| 主体 | `CN=*.xidian.edu.cn, O=Xidian University` |

**fail-closed 语义（不可关闭）**：

- 指纹不匹配 → 打印 `TLS_PIN_MISMATCH`，立即中止握手，**凭据绝不发出**；
- 构建中未提供指纹 → 同样拒绝认证（`config/campus_tls_pin.h` 的 fail-closed 默认）；
- **绝不回退 `setInsecure()`**。

证书 2026-11-17 到期后本 Pin 失效，需按 `campus_tls_pin.h` 中的 `openssl` 流程重抽并更新**所用 Profile** 的 `CAMPUS_CERT_*` 宏（不要写回 `campus_tls_pin.h`）。完整流程见 [TLS 证书固定与更新](../../firmware/agent-platformio/docs/03_协议与接口/TLS证书固定与更新.md)。

### 5. 配置校园网凭据

凭据必须保存在 **git-ignored** 的 `campus_secrets.h` 中：

```bash
cd firmware/shared/RemoteACCore/src/config
cp campus_secrets.example.h campus_secrets.h
# 编辑 campus_secrets.h，填入你自己有权使用的学号和密码
```

```cpp
// campus_secrets.h（git-ignored，绝不提交）
#define CAMPUS_USERNAME "your_student_id"
#define CAMPUS_PASSWORD "your_password"
```

**凭据仅在你额外显式设置 `ENABLE_CONTROLLED_LIVE_AUTH=1` 时才参与编译。** 在默认构建中，即使 `campus_secrets.h` 存在，其内容也不会进入固件二进制——这是防止误发布含凭据固件的第二道闸门。

```cpp
// 仅在你确认要进行真实认证时，在 globals.h 中加上这一行
#define ENABLE_CONTROLLED_LIVE_AUTH 1
```

未开启时，认证路径会在串口打印 `CAMPUS_CREDS_READY=DISABLED REAL_AUTH_REQUEST_ALLOWED=BLOCKED_BY_BUILD_POLICY` 并停止，不会向门户发出任何登录请求。

## 串口输出状态

认证过程中，串口（115200 波特率）输出的标记如下：

```
WIFI_CONNECT source=CAMPUS_PROFILE_OPEN ssid=stu-xdwlan security=OPEN
WIFI_ASSOC_PASS
LOCAL_IP=10.x.x.x
GATEWAY=10.x.x.1
DNS_IP=10.x.x.1
PORTAL_DETECT_START
PORTAL_PROBE_TARGET label=baidu host=www.baidu.com
  HTTP_CODE=302
  LOCATION=https://w.xidian.edu.cn/index_8.html
PORTAL_DETECT_RESULT captive=YES
CAPTIVE_PORTAL_DETECTED=YES
PORTAL_HOST=w.xidian.edu.cn
AC_ID=8
CAMPUS_AUTH_START
CAMPUS_AUTH_PASS
INTERNET_VERIFY round=1 ok=YES cumulative_ok=1
INTERNET_VERIFY round=2 ok=YES cumulative_ok=2
INTERNET_VERIFY round=3 ok=YES cumulative_ok=3
INTERNET_ONLINE
```

门户探测会依次尝试 3 个目标：`baidu`（`http://www.baidu.com/`）、`miui_204`（`http://connect.rom.miui.com/generate_204`）、`msft_ncsi`（`http://www.msftncsi.com/ncsi.txt`）。互联网验证需**连续 3 轮全部成功**才判定 `INTERNET_ONLINE`。

常见失败输出：

```
TLS_PIN_MISMATCH                       # 指纹不匹配，凭据未发送，进入 BLOCKED
CAMPUS_AUTH_FAIL reason=BAD_CREDENTIALS
AUTH_SERVER_ERROR=<门户返回的 error 字段>
AUTH_BACKOFF ms=<退避毫秒> fail_streak=<连续失败次数>
CAMPUS_CREDS_READY=NO
AUTH_BLOCKED_NEEDS_LOCAL_CREDENTIALS   # 未配置凭据或未开 ENABLE_CONTROLLED_LIVE_AUTH
AUTH_RESPONSE_OK_BUT_INTERNET_BLOCKED  # 门户回 OK 但连通性验证未过 3/3
CAPTIVE_PORTAL_DETECTED=NO
```

**密码被拒绝（`BAD_CREDENTIALS`）、域错误（`WRONG_DOMAIN`）、指纹不匹配（`TLS_PIN_MISMATCH`）属于硬失败**，会锁存进 `WIFI_BLOCKED` 状态且不再自动重试——自动重放被拒绝的密码正是校园账号被锁定的典型原因。

解除锁存有三种方式：

| 方式 | 行为 |
|------|------|
| `campus unblock` | 清除锁存并**从门户探测重新进入**流程；无需编入凭据即可使用 |
| `campus login` | 清除锁存并**立即发起一次登录**；要求凭据已编入（`ENABLE_CONTROLLED_LIVE_AUTH=1`） |
| 重新上电 | 全状态复位 |

串口 CLI 的 campus 子命令完整集合为 `status | login | logout | unblock`。

## 安全说明

- **凭据仅存在于本地 git-ignored 文件**，且需二次开关 `ENABLE_CONTROLLED_LIVE_AUTH=1` 才编入固件；
- TLS 叶证书指纹固定，**fail-closed**，任何情况下不得关闭校验或回退 `setInsecure()`；
- 具备认证频率限制（每小时配额）与指数退避，硬失败 latch 防止账号锁定；
- 日志中不打印完整账号密码；`LOCATION` 字段的 query 串会被剥离，避免泄露 token；
- Portal 响应不完整打印，避免泄露敏感信息；
- 仓库中提交的 `xidian.example.h` **不含**任何账号、密码、Cookie、Token 或私钥。

## 限制

- 本 Profile **仅针对西电校园网（Srun 4000）** 适配；
- TLS 指纹在 **2026-11-17** 后失效，届时必须重抽，否则认证会 fail-closed 拒绝；
- 其他学校的 Srun 系统需要调整 Profile 参数，见 [Srun 校园网移植指南](./Srun校园网移植指南.md)；
- 默认不启用自动认证，需用户显式配置；
- 用户必须使用**自己有权使用**的校园网账号，并遵守学校网络使用规定。
