# 维护者发布流程

本文档供仓库维护者使用，定义从提交到发布 v1.2.x 的完整流程。

## 发布前检查

- 在干净工作树、当前 `main` 上创建发布准备分支（`release/vX.Y.Z`）。
- 本地通过：`tools/test-all.ps1`、`tools/build-all.ps1`，以及
  `check-doc-parity.py` / `check-doc-links.py` / `check-doc-language-links.py` /
  `check-public-docs.py` / `check-version.py` / `check-pcb-release.py`。
- 中英文文档必须成对同步（`docs/中文/` ↔ `docs/English/`），并更新
  `docs/doc-map.json`。
- 运行秘密/私钥/数据库/真实 IR 排除扫描，确认公开树 0 命中。

## 版本与标签

- 版本统一由根 `VERSION` 决定，`check-version.py` 动态校验全部版本文件。
- 软件版本（vX.Y.Z）与 PCB 修订（Rev x.y.z）相互独立。
- 发布时创建 **annotated tag**（如 `v1.2.1`），只推送该 tag，不用
  `git push --tags`。
- **标签一旦推送即不可移动、不可重写**。需要修复时发布新补丁版本。

## Release 资产规则

- **已发布的资产不得静默替换。** 如果发布后发现资产错误，发布补丁版本
  （v1.2.1 → v1.2.2），并在旧 Release 正文顶部加入"已被取代（superseded）"
  的中英文警告。
- 标签后必须**重新下载全部资产**（含 GitHub 自动源码 zip/tar.gz），逐文件
  核对 SHA256 后再对外公告。
- 制造类资产使用确定性打包（`tools/package-pcb-release.py`），同一 commit
  两次打包 SHA256 必须一致。
- `SHA256SUMS.txt` 记录所有 Release 资产的 SHA256，随 Release 一并发布。
- Release 正文需要人工整理，不能直接使用自动生成的草稿。

## PCB 发布

- PCB 制造包只包含 `gerber/`、`drill/`、`test/FlyingProbeTesting.json`、
  `manufacturing-manifest.md`、`PCB下单必读.txt`。
- EasyEDA 源文件保留在标签源码树，默认不进入制造 ZIP。
- 制造包内文件哈希必须与 `manufacturing-manifest.md` 记录的哈希一致，
  且两者都基于 Git 受控字节（不受换行设置影响）。
- 详见 [PCB 发布流程](./PCB发布流程.md)。

## 禁止事项

- 不得把 `Private/`、`Evidence/`、`Archives/`、`Deliverables/` 或生产数据
  写入公开仓库。
- 不得公开生产服务器、域名、MQTT 凭据或真实红外帧。
- 不得重写已推送的历史或移动已发布的标签。
