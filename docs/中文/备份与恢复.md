# 备份与恢复

本文件介绍 Remote AC Controller 公开仓库的备份与恢复通用做法。它替换了早期的内部交接文档，仅保留对自托管部署者有用、且不暴露任何生产标识的内容。

> 本文档不涉及任何生产服务器、生产凭据、内部发布门禁或历史事故时间线。所有示例均使用占位值（如 `example.com`、`203.0.113.0/24`、`C:/example/remote-ac`）。

## 1. 需要备份的内容

| 类别 | 说明 | 敏感性 |
|------|------|--------|
| 源码仓库 Bundle | 完整的 Git 仓库快照（`git bundle` 或带所有引用的镜像），用于在无法访问远程时恢复源码 | 低（公开源码） |
| 数据库 | 云端后端使用的 `node:sqlite` 数据库文件及其转储 | 高（含设备/会话元数据） |
| 配置 | 自托管部署的 `.env`、TLS 证书、MQTT ACL、反向代理配置 | 高（含密钥） |
| 红外码库 | 你为自有空调机型捕获的红外学习文件 | 中（仅对你自己的设备有效） |

## 2. 源码仓库 Bundle 备份

```bash
# 在仓库根目录执行，生成自包含的 bundle 文件
git bundle create remote-ac-backup.bundle --all
# 校验 bundle 可被正常克隆
git clone ./remote-ac-backup.bundle /tmp/verify-clone
```

建议：将 bundle 存放在离线或异地介质；定期重新生成以纳入新提交。

## 3. 数据库安全备份

云端后端使用内置 `node:sqlite`。请通过应用提供的导出接口或直接在停机窗口复制数据库文件：

```bash
# 示例：在维护窗口停机后端后复制数据库（占位路径）
cp C:/example/remote-ac/cloud/backend/data/app.db C:/example/remote-ac/backup/app.db.$(date +%F)
```

- 备份时尽量让后端处于停机或只读状态，避免复制到写入中途的文件。
- 数据库备份含设备与会话元数据，**必须加密存储**，且不要随源码仓库提交。

## 4. 配置备份

- 将 `.env`（及 `.env.example` 之外的真实配置）单独备份，**绝不要**提交到 Git。
- TLS 证书（`fullchain.pem`、`privkey.pem`）与 MQTT 凭据单独加密归档。
- 建议为配置备份建立与源码不同的访问控制。

## 5. 恢复流程

1. **恢复源码**：`git clone ./remote-ac-backup.bundle ./restored` 或 `git clone <remote-url>`。
2. **恢复依赖**：在 `cloud/backend` 与 `cloud/frontend` 执行 `npm ci`。
3. **恢复数据库**：停机后端，用备份文件覆盖数据库路径，确认文件未被截断。
4. **恢复配置**：将备份的 `.env`、证书、ACL 放回对应目录，核对文件权限。
5. **冒烟验证**：启动后端，调用 `/api/health`，确认返回正常。

## 6. 回滚原则

- 数据库迁移靠幂等 `ALTER TABLE` 保证向前兼容；**反向降级未经验证**，降级前务必先完成数据库备份。
- 代码回滚优先使用 `git` 的历史提交或已发布的 tag，避免手工修改线上文件。
- 回滚后必须重新执行第 5 节的冒烟验证。

## 7. 如何验证恢复

- **源码完整性**：`git fsck --full` 无错误；`git log --oneline -1` 与备份时一致。
- **数据库可用**：后端启动无 `ERR_UNKNOWN_BUILTIN_MODULE` 或数据库打开错误；`/api/health` 返回 200。
- **配置生效**：后端日志显示绑定到预期地址（如 `localhost` 或你的内网地址）；TLS 握手成功。
- **功能验证**：读取一次设备遥测或下发一次测试命令，确认端到端链路正常。
