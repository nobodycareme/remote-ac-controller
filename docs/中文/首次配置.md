# 首次配置指南

本指南介绍三种常见的首次配置方式：普通家庭/实验室 WPA/WPA2 WiFi、西电 Srun 校园网、以及不配置任何真实凭据的公开构建。所有真实凭据（WiFi 密码、校园账号密码）只存放在本地文件中，仓库内只提交 `.example.h` 模板。

固件的功能开关统一由 [`firmware/shared/RemoteACCore/src/config/feature_gates.h`](../../firmware/shared/RemoteACCore/src/config/feature_gates.h) 控制，各开关组合在该头文件中以编译期 `#error` 形式强制校验。

---

## A. 普通家庭/实验室 WPA 或 WPA2 WiFi

> 适用场景：家庭或办公室 WiFi 为 WPA/WPA2 加密（密码至少 8 位），不需要 Portal 认证。

### A.1 准备本地凭据

```powershell
cd firmware/shared/RemoteACCore/src/config
cp wifi_secrets.example.h wifi_secrets.h
```

编辑 `wifi_secrets.h`：

```cpp
#define LOCAL_WIFI_SSID     "你的WiFi名称"
#define LOCAL_WIFI_PASSWORD "你的WiFi密码"
```

> `wifi_secrets.h` 只保存在本地并已被 Git 忽略，不要将真实密码写进 README、platformio.ini 或提交记录。

### A.2 选择 PlatformIO 编译 Profile

`dev.ps1` 提供两个本地 WiFi Profile：

| Profile | 含义 | ENABLE_CLOUD |
|---|---|---|
| `local-wifi` | 家庭/实验室 WiFi，无云连接 | 0 |
| `local-wifi-cloud` | 家庭/实验室 WiFi + 云端（MQTT/HTTPS） | 1 |

```powershell
cd firmware/agent-platformio
./tools/dev.ps1 build -Profile local-wifi
./tools/dev.ps1 build -Profile local-wifi-cloud
```

### A.3 Arduino IDE 模式

在 Arduino IDE 中打开 `firmware/arduino-ide/Remote_AC_Controller/Remote_AC_Controller.ino`，在 `globals.h` 中配置：

```cpp
#define ENABLE_WIFI              1
#define ENABLE_WIFI_CREDENTIALS  1   // 启用本地 WPA 凭据
#define ENABLE_AUTO_WIFI_CONNECT 1   // 上电自动连接

// 普通 WiFi 凭据（与 PlatformIO 路径相同）
#include "config/wifi_secrets.h"
```

> 通用 Arduino IDE 操作见 [Arduino IDE 使用指南](Arduino-IDE使用指南.md)。

### A.4 运行时串口命令

固件上电后会用编译进二进制的本地凭据连接家庭 WiFi。如需手动连接或切换到开放 SSID，可在串口 monitor 中执行：

| 命令 | 行为 |
|---|---|
| `wifi connect` | 重新连接 `wifi_secrets.h` 中的家庭 WiFi（WPA 路径，密码不入串口） |
| `wifi connect stu-xdwlan` | 显式连接西电开放 SSID（`wifi_secrets.h` 不被读取） |
| `wifi status` | 打印当前连接状态 |
| `wifi scan` | 列出附近 AP（只读） |
| `wifi disconnect` | 断开当前关联 |

串口日志中不会输出密码内容，只输出：

```
WIFI_CONNECT ssid=<ssid> security=WPA_OR_WPA2
WIFI_CONNECT ssid=<ssid> security=OPEN
```

## B. 西电 Srun 校园网

> 适用场景：西电校园 WiFi `stu-xdwlan`（开放 SSID，无 WPA 密码），需要 Portal 认证。
> 注意：西电 Srun 仅作为公开示例 Profile（`profiles/xidian.example.h`）。其他 Srun 部署可参考 [Srun 校园网移植指南](Srun校园网移植指南.md)。

### B.1 PlatformIO 公开示例

```powershell
cd firmware/agent-platformio
./tools/dev.ps1 build -Profile local-campus-example
```

`local-campus-example` 只用于安全的公开编译验证：它编译校园认证代码，验证其能够构建，但**不读取真实校园账号密码、不会执行真实登录**。该 Profile 将 `ENABLE_AUTO_CAMPUS_AUTH=0` 与 `ENABLE_CONTROLLED_LIVE_AUTH=0`，因此不会在开机时自动认证，也不接受真实凭据。

### B.2 真实校园认证（Arduino IDE）

目前公开仓库中可验证的真实配置入口是 Arduino IDE 的本地 `globals.h` 配置。在 `firmware/arduino-ide/Remote_AC_Controller/Remote_AC_Controller.ino` 中：

```cpp
#define ENABLE_WIFI                 1
#define ENABLE_CAMPUS_AUTH          1
#define ENABLE_AUTO_WIFI_CONNECT    1
#define ENABLE_AUTO_CAMPUS_AUTH     1
#define ENABLE_CONTROLLED_LIVE_AUTH 1
#define CAMPUS_PROFILE_HEADER       "profiles/xidian.h"
```

并使用两个本地文件（均被 Git 忽略，不会提交）：

```powershell
cd firmware/shared/RemoteACCore/src/config
cp profiles/xidian.example.h profiles/xidian.h
cp campus_secrets.example.h campus_secrets.h
```

编辑 `campus_secrets.h`：

```cpp
#define CAMPUS_USERNAME "你的学号"
#define CAMPUS_PASSWORD "你的校园网密码"
```

> `xidian.h` 与 `campus_secrets.h` 均不会被提交；不要在 `platformio.ini` 或 `globals.h` 中写明文密码。

安全要求：

- 不要关闭 TLS 校验（不使用 `setInsecure()`）；
- TLS 指纹不匹配时必须停止认证，`BAD_CREDENTIALS` / `WRONG_DOMAIN` / `TLS_PIN_MISMATCH` 会进入 `BLOCKED` 状态，不会自动高频重试；
- 每小时配额、最小间隔、失败退避与硬阻断闩锁由 `campus_auth_policy.h` 统一控制。

完整细节见 [西电校园网自动认证](西电校园网自动认证.md)。

## C. 无凭据公开构建

> 适用场景：只想编译一次验证公开固件能否安全构建，不需要任何真实凭据。

```powershell
cd firmware/agent-platformio
./tools/dev.ps1 build -Profile public
```

`public` Profile 会编译 WiFi 和云端模块，但：

- 不编译真实 WiFi、校园网或 MQTT 凭据（`cloud_secrets.h` 仍为 example 占位符）；
- 默认不在上电时自动连接网络（`ENABLE_AUTO_WIFI_CONNECT=0`）；
- 适合检查公开固件能否安全编译。

这不是完全离线构建：固件仍包含 WiFi 与云端代码路径，只是不携带任何真实凭据。
