# 校园网认证说明（实现与流程）

> 本文件描述 NodeMCU ESP8266 上校园网认证的端到端实现：从 Wi-Fi 关联到
> srun v2 登录、TLS 固定、状态机与受控重试。旧自制实现（`archive/rejected_auth_implementation/`）
> 已废弃，全部改用 vendored `srun-c`（见 `第三方_srun-c_来源与版本.md`）。
> 早期设计稿见 `docs/09_校园网接入/校园网集成设计说明.md`（仅作历史参考，本文档为权威）。

## 1. 总体架构

```
main.cpp
  └─ WifiManager (src/network/wifi_manager.cpp)
       ├─ ESP8266WiFi        关联 stu-xdwlan / DHCP
       ├─ doPortalDetect()   INSECURE_PROBE_ONLY 门户探测（无凭据）
       ├─ doAuth()           CampusAuthVendor::login(localIp)
       │     └─ lib/srun-c    HMAC-MD5 + x_encode + {SRBX1} + srun Base64
       │           └─ esp8266_http_adapter_secure.cpp  setFingerprint(CAMPUS_CERT_SHA1)
       └─ doVerifyInternet() 3 轮外部连通性验证（baidu.com 不被拦截）
```

- 认证算法与 HTTP 适配全部来自 vendored `srun-c`，本仓库仅修改其 ESP8266 适配器
  以启用证书固定。
- DHT11（D1/GPIO5）、红外（D5/D6）与校园网认证相互独立，互不影响。

## 2. 网络状态机（10 态）

`DISCONNECTED → ASSOCIATING → DHCP_WAIT → PORTAL_CHECK → AUTH_READY →
AUTHENTICATING → VERIFYING_INTERNET → ONLINE → BACKOFF → BLOCKED`

关键规则：
- `BAD_CREDENTIALS` / `WRONG_DOMAIN` / `TLS_PIN_MISMATCH` → 直接进入 `BLOCKED`，
  **不自动重试、不踢其他终端、不自动注销**。
- 其它可恢复错误（超时等）进入 `BACKOFF`，指数退避 `30 / 60 / 120 s`，最多有限次。
- `ONLINE` 期间每 5 分钟检查一次外部连通性，连续 2 次失败回到 `PORTAL_CHECK`。
- `doPortalDetect()` 是唯一的 `INSECURE_PROBE_ONLY` 路径，仅探测不登录。

## 3. 受控真实登录（Phase 9）

仅在**三重门禁全过**后发起：
1. `CAMPUS_CREDS_READY=YES`
2. `TLS_PIN_STATUS=VALID`
3. `SRUN_ALGORITHM_VECTOR_PASS` + 参数门禁（`SSID=stu-xdwlan`/`DOMAIN=DEFAULT_CAMPUS`/
   `OPERATOR_SUFFIX=NONE`/`AC_ID=8`）

登录策略：
- 首次尝试 1 次；仅在 `TIMEOUT` 类错误时重试，最多 1 次首试 + 2 次重试。
- `BAD_CREDENTIALS` / `WRONG_DOMAIN` / `TLS_PIN_MISMATCH` **立即终止，不重试**。
- 不自动注销、不踢其他已登录终端。

日志（仅以下，无凭据）：
`CAMPUS_AUTH_START`、`CHALLENGE_HTTP_STATUS`、`CHALLENGE_PARSE`、
`LOGIN_HTTP_STATUS`、`LOGIN_RESULT_CLASS`、`CAMPUS_AUTH_PASS` /
`CAMPUS_AUTH_FAIL reason=<class>`。

## 4. 互联网连通性验证（Phase 10）

登录接口成功后，进行 3 轮外部验证（间隔 2–5 秒）：
- 3 轮全部通过 → `INTERNET_ONLINE`。
- 仍被门户拦截 → `AUTH_RESPONSE_OK_BUT_INTERNET_BLOCKED`。

## 5. 当前状态与判定

- 真实账号密码**不在本仓库**（无 `secrets.h`），故默认 `CAMPUS_CREDS_READY=NO`，
  设备进入 `AUTH_BLOCKED_NEEDS_LOCAL_CREDENTIALS`：编译通过 ≠ 认证成功。
- 何时判定 `ALL_PHASES_PASS`：仅在真实凭据就位、clean build 通过、现场受控登录
  + 三方可连通性全部通过后，由用户现场确认空调可被远程唤醒。
- 未满足上述条件时，整体判定为 `AUTH_BLOCKED`（凭据缺失）或 `PARTIAL_PASS`，
  **不得**标记为认证成功。
