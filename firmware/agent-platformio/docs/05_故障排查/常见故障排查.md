# 常见故障排查

## A. 构建 / 环境类
| 症状 | 原因 | 处理 |
|------|------|------|
| `pio run` 卡在 `Processing nodemcuv2` | 设了 `PLATFORMIO_OFFLINE=1`（6.1.19 registry 解析挂死，K12） | **不要**设该变量；改用 `NO_PROXY` 直连绕过 MITM 代理 |
| 下载 `*.platformio.org` / `*.espressif.com` TLS 失败或极慢 | 本地 MITM 代理 `127.0.0.1:10808` 破坏 TLS | 设 `NO_PROXY=".platformio.org,platformio.org,.espressif.com,espressif.com,127.0.0.1,localhost"` |
| Bash 里编译错误被“吞掉” | 用了 `\| tee`，pio re-exec 子进程输出丢失 | 改用 `pio run > log 2>&1`；后台加 `echo "BUILD_DONE_EXIT=$?" >> log` |
| 离线安装工具后 `pio run` 仍慢速远程下载 | `.piopm` 的 `spec.owner=null` 与平台 `owner=platformio` 不匹配（K2） | 把工具 `.piopm` 的 `owner` 改为 `platformio`（仅该字段） |
| `file:///F:/...` 安装报 `WinError 123` | 三斜杠被解析成非法路径 `/F:/...`（K1） | 用两斜杠 `file://F:/...` |
| PowerShell 脚本里 `$env:` 被误解释 | 用 Bash 跑了 PowerShell 脚本 | `.ps1` 必须用 PowerShell 工具执行，不能用 Bash |
| 串口采集脚本 gbk 编码崩溃（K6） | Windows 默认 gbk | `serial_collect.py` 已 `reconfigure(utf-8)` + `PYTHONUTF8=1` |

## B. 烧录 / 串口类
| 症状 | 处理 |
|------|------|
| 找不到 COM 口 | 端口运行时动态检测；确认 CH9102 驱动（VID:PID `1A86:55D4`），插紧数据线 |
| 端口被占用无法烧录 | 先关闭串口监视器 / 释放端口，再 upload |
| 采集不到开头样本 | 采集接入晚于上电属正常；以 `*_SUMMARY` 汇总行 + 连续样本编号为准 |

## C. DHT11 / XHT11 温湿度类
| 症状 | 原因 | 处理 |
|------|------|------|
| 读数全 NaN / bit-end-timeout | 优先怀疑**测试方法**（自定义驱动/临界区打印），而非直接归咎硬件或某引脚 | 用 Adafruit 库 + **D1/GPIO5** 复测（见历史问题与结论修正） |
| 用自定义 bit-bang 驱动卡高 | 临界区内串口打印破坏时序 | 禁用自定义驱动，改 Adafruit 标准库 |
| 读取偶发失败 | 采样过快 | 间隔 ≥2.5s（Adafruit 强制 ≥2s） |
| 想换回 GPIO4 | 旧测试同时换库与引脚，GPIO4 是否独立异常未单变量验证 | 当前正式方案为 D1/GPIO5（Adafruit 已验证稳定）；改脚只改 `hardware_config.h` 一处，且须经用户确认 |

## D. 红外（ZJ-IR-V2）类
| 症状 | 处理 |
|------|------|
| 探测无回复 | 确认 TXD→D5、RXD→D6 未接反；共地；波特率 115200 8N1 |
| 无 RX 中断 | SoftwareSerial 惰性开启，未 begin 则无 RX；先经 CLI 开启探测 |
| 想改地址/波特率/发码 | 需用户显式授权；探测到 115200 想改 9600 须先停并解释 |

## E. 通用定位法
1. 先隔离“测试方法”变量：换**标准库** + 换**已知良好引脚** + **最小化环境**。
2. 严格时序协议里，临界区禁止阻塞输出。
3. 保留原始日志与 `*_SUMMARY` 行作为权威判据。
4. 破坏性操作前先做**工程外备份**（见 `F:\PIO\Archives`）。
