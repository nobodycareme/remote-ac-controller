# IR Protocol Analysis — ZJ-IR-V2 红外学习/发射模块

## 1. 模块硬件信息（来源：使用说明书 V1.0.6，p.6–7）

- 型号：红外学习模块基础版（ZJ-IR-V2 为本次实物，TTL 接口版本）
- MCU（原理图 485 版）：STC8G1K80A（仅 485 版参考，TTL 版引脚丝印一致）
- 尺寸：16 × 16 × 1.6 mm
- 工作电压：**3.3 ~ 5 V**（说明书写“5V 供电效果最佳”）
- 工作电流：5 ~ 30 mA
- 红外载波频率：**38 kHz**
- 遥控距离：5 ~ 8 米
- 通讯接口：**TTL**（实物丝印 GND / TXD / RXD / VCC）
- 器件方向（p.6 + 测试步骤）：
  - **黑色器件 = 红外接收头（J3）**：学习时遥控器对准它
  - **透明器件 = 红外发射管（J2）**：发射时对准空调接收窗

## 2. TTL 接口定义（来源：说明书 p.6 硬件介绍；原理图 J1）

| 模块丝印 | 方向 | 连接 |
|---|---|---|
| VCC | 电源 | NodeMCU 3V3（当前阶段 3.3V） |
| GND | 地 | NodeMCU GND（共地） |
| TXD | 模块输出 | → NodeMCU D5 / GPIO14（软件串口 RX） |
| RXD | 模块输入 | ← NodeMCU D6 / GPIO12（软件串口 TX） |

> 注意：TXD 是模块发往主控的线，RXD 是主控发往模块的线。
> 代码：`SoftwareSerial irSerial(IR_RX_PIN, IR_TX_PIN);` 即 `SoftwareSerial(D5, D6);`
> 构造函数顺序为 **(RX, TX)**，禁止写成 `(D6, D5)`。

## 3. 当前接线（与用户确认）

- ZJ-IR-V2 VCC → NodeMCU 3V3
- ZJ-IR-V2 GND → NodeMCU GND
- ZJ-IR-V2 TXD → NodeMCU D5 / GPIO14
- ZJ-IR-V2 RXD → NodeMCU D6 / GPIO12

## 4. 工作电压（来源：说明书 p.7）

当前阶段使用 **3.3V** 供电（符合用户指令第 3 条：首次测试必须 3.3V，不得因“5V 最佳”擅自改 5V）。
若后续需 5V 增大发射距离，须先确认模块 5V 时 TXD 高电平、是否超 ESP8266 3.3V、是否需要电平转换，并经用户明确同意。

## 5. 初始供电方案

NodeMCU 3V3 直供，模块与 NodeMCU 共地。USB 调试串口与红外软件串口相互独立。

## 6. 默认串口参数（来源：说明书 p.8 字节格式）

- **默认波特率：115200 bps**（8 数据位、1 停止位、无奇偶校验、无流控）
- 这是一个多字节字段，低字节在前（little-endian）。

> 冲突处理：Arduino_Nano_IrStudy.ino 示例以 `mySerial.begin(9600)` 运行，但说明书（优先级 b）明确默认 115200。
> 依据资料冲突优先级（实物 > 说明书 > 测试步骤 > .ino > 485 原理图），**以说明书为准：默认 115200**。
> 但 .ino 在 9600 下可工作，说明该模块也可能被预先设为 9600。因此 Phase 3 探测顺序为
> **[115200, 9600, 57600, 38400, 19200]**，两者都优先尝试，确保无论模块实际波特如何都能建立通信。

## 7. 红外载波频率（来源：说明书 p.4、p.7）

38 kHz。

## 8. 内部存储组数量（来源：说明书 p.4–5）

最多 **7 组**（索引 0 ~ 6），每组 512 字节（前 2 字节为编码长度，后 510 字节为红外编码数据）。
当前第一阶段仅使用索引 **0**。

## 9. 红外学习流程（来源：说明书 p.19–20；测试步骤 五）

1. 下发 `AFN=10H`（进入内部编码存储学习模式）+ 组索引 → 模块回复应答帧 `AFN=01H`，**绿色指示灯常亮**。
2. 用户用遥控器对准黑色接收头，按一次目标键 → 指示灯**熄灭**，模块发送上报帧 `AFN=02H`（标志 0x80 = 学习并存储成功）。
3. 学习完成，自动退出学习模式。

## 10. 红外发射流程（来源：说明书 p.21–22；测试步骤 六）

1. 下发 `AFN=12H`（发送内部存储红外编码）+ 组索引 → 模块回复应答帧 `AFN=01H`（命令被接受）。
2. 模块将存储的编码调制到 38 kHz 载波，通过红外发射管发出，**板载指示灯闪烁一次**。
3. 空调是否实际响应，须由用户目视确认（不得把模块回包等同于空调响应）。

## 11. 帧头（来源：说明书 p.8 帧格式）

固定 `0x68`。

## 12. 长度字段（来源：说明书 p.8）

2 字节，little-endian，表示**整帧所有字节的长度**（含帧头与帧尾）。
例：`68 08 00 ...` → 长度 = 0x0008 = 8 字节。

## 13. 模块地址（来源：说明书 p.8）

1 字节。**默认地址 `0x00`**；**广播地址 `0xFF`**。
所有下发报文地址须等于模块地址或 `0xFF` 才响应。

> ⚠️ 关键：模块**上行（应答/上报）帧使用模块自身地址（默认 0x00）**，不是 0xFF。
> 因此解析回包时地址字段应为 `0x00`（或已配置的地址），解析器同时接受 `0x00` 与 `0xFF`，
> 并以帧头/帧尾/校验和/AFN 作为主校验依据。

## 14. 广播地址

`0xFF`（所有下发报文均可使用）。

## 15. 功能码 AFN（来源：说明书 p.10–11，已逐条核对）

| AFN | 含义 | 是否本阶段使用 |
|---|---|---|
| 01H | 应答帧 | 是（解析） |
| 02H | 上报帧 | 是（解析，学习成功标志） |
| 03H | 设置波特率 | 仅用户明确授权后 |
| 04H | 获取波特率 | 是（探测/info） |
| 05H | 设置模块地址 | **禁止**（未授权） |
| 06H | 获取模块地址 | 是（info，只读） |
| 07H | 复位 | **禁止** |
| 08H | 格式化 | **禁止** |
| 10H | 进入内部编码学习 | 是（ir learn，需授权） |
| 11H | 退出内部编码学习 | 是（ir cancel / 安全退出） |
| 12H | 发送内部存储编码 | 是（ir send，需授权） |
| 13H | 设置上电自动发码 | **禁止** |
| 14H | 获取上电自动发码 | 否 |
| 15H/16H | 上电发码延时 | 否 |
| 17H | 写入内部编码 | **禁止** |
| 18H | 读取内部编码 | 否 |
| 20H/21H/22H | 外部存储学习/发送 | 否（本阶段用内部存储） |

## 16. 数据域

变长，随 AFN 而定。例如：
- 进入/发送学习：1 字节 = 组索引（0~6）
- 设置波特率：1 字节 = 波特率索引（0~4）
- 获取波特率回包：1 字节 = 波特率索引

## 17. 校验和算法（来源：说明书 p.8；.ino 印证）

`CS = (模块地址 + AFN + 所有数据域字节) 对 256 取余`（即低 8 位 / 模 256）。
**校验和覆盖区间：从“模块地址”字节开始，到最后一个“数据域”字节结束，不含帧头、长度、校验和自身、帧尾。**

C 代码：
```c
uint8_t cs = addr;
cs = (uint8_t)(cs + afn);
for (i = 0; i < dataLen; i++) cs = (uint8_t)(cs + data[i]);
// cs 即为校验字节（已自然取低 8 位）
```

## 18. 帧尾（来源：说明书 p.8）

固定 `0x16`。

## 19. 多字节字段高低字节顺序（来源：说明书 p.8）

低字节在前、高字节在后（little-endian）。长度字段、延时字段（2 字节）均如此。

## 20. 每条项目所需指令及其计算过程（来源：说明书 p.13–22，已逐字节验证）

### (a) 查询当前波特率 AFN=04H（无数据域）
- 下发：`68 07 00 FF 04 03 16`
  - 长度=07 00（7 字节），地址=FF，AFN=04，数据域=空，CS=(FF+04)=0x103→0x03，尾=16 ✓
- 上行：`68 08 00 00 04 04 08 16`
  - 地址=00（模块自身），AFN=04，数据=04（波特率索引 4 = 115200），CS=(00+04+04)=0x08 ✓

### (b) 设置波特率为 9600 AFN=03H（数据=00，索引 0）
- 下发：`68 08 00 FF 03 00 02 16`
  - 长度=08，地址=FF，AFN=03，数据=00，CS=(FF+03+00)=0x102→0x02，尾=16 ✓
- ⚠️ 属持久化操作，须经用户明确授权后才发送（见说明书 p.12，波特率索引表）。

### (c) 进入第 0 组学习 AFN=10H（数据=00，组索引 0）
- 下发：`68 08 00 FF 10 00 0F 16`
  - CS=(FF+10+00)=0x10F→0x0F ✓
- 上行应答：`68 08 00 00 01 00 01 16`（AFN=01，状态字）
  - 说明：本测试用例状态字=00 表示成功（见 p.20 与 p.11 状态字定义；注意 p.20 用例中状态字节写作 01，
    与 p.11“0=成功/1=拒绝”描述存在手册内部不一致，固件以“收到结构合法应答帧”为进入学习模式判据，
    并以 AFN=02 上报帧（标志 0x80）作为学习真正成功判据）。
- 学习成功上报：`68 0A 00 00 02 80 00 00 82 16`
  - 长度=0x0A=10，地址=00，AFN=02，数据=80（标志 0x80=学习并存储成功）00（索引 0）00（上报状态 0=成功），
    CS=(00+02+80+00+00)=0x82 ✓，尾=16 ✓

### (d) 退出内部学习 AFN=11H（无数据域）——来源：说明书 p.20–21（AFN=11H 章节）
- 下发：`68 07 00 FF 11 10 16`
  - CS=(FF+11)=0x110→0x10 ✓
- 上行应答：`68 08 00 00 01 00 01 16`（AFN=01，状态 00=成功）
- 用途：`ir cancel` 安全退出学习模式；正常学习在收到遥控器信号后自动退出。

### (e) 发射第 0 组 AFN=12H（数据=00，组索引 0）
- 下发：`68 08 00 FF 12 00 11 16`
  - CS=(FF+12+00)=0x111→0x11 ✓
- 上行应答：`68 08 00 00 01 00 01 16`（AFN=01，状态 00=命令被接受）
- 空调是否实际响应须用户目视确认。

## 21. 预期应答

- 控制类命令（进入学习 10H、发射 12H、退出学习 11H、设置波特率 03H 等）：返回 **应答帧 AFN=01H**，数据域 1 字节状态字（0=成功接受并执行，1=参数错误或繁忙拒绝）。
- 查询类命令（获取波特率 04H、获取地址 06H 等）：返回**同 AFN 的响应帧**，数据域为返回值（不含 01H 应答）。
- 学习完成：返回**上报帧 AFN=02H**（标志 0x80 + 组索引 + 上报状态）。

## 22. 主动上报帧（来源：说明书 p.11–12）

- 触发：内部学习时用户按遥控器；上电自动发码时。
- 结构：`68 <LEN_L><LEN_H> <ADDR> 02 <FLAG> <INDEX> <STATUS> <CS> 16`
  - FLAG：0x80 = 学习并存储成功；0x81 = 上电自动发码已发送
  - INDEX：0~6
  - STATUS：0 = 成功，1 = 失败

## 23. 超时策略（固件实现）

- 每个红外操作设置独立超时（查询 ~800 ms；学习等待用户按键最长 ~30 s 并可被 `ir cancel` 中止）。
- 接收解析采用“缓冲 + 扫描合法帧”方式，避免因起始垃圾字节或数据域内出现 0x68/0x16 造成误判。
- 超时或校验失败不得永久阻塞主循环；DHT11 定时读取不受影响。

## 24. 资料之间的冲突

1. **默认波特率**：.ino 用 9600；说明书 p.8 明确默认 115200。
   处理：按优先级以说明书为准（默认 115200），但探测顺序同时优先尝试 9600。
2. **进入学习应答状态字**：说明书 p.20 用例写作 01，p.11 定义 0=成功。
   处理：固件以“收到结构合法应答帧”判定进入学习模式，以 AFN=02 上报帧（0x80）判定学习真正成功。
3. **485 原理图**：含 MAX485 / A-B 差分 / J4=485，属 RS-485 版本，与当前 TTL 模块不一致，仅作辅助，
   不改变 TTL 接线（依据优先级 e）。

## 25. Arduino Nano 示例中可复用于 ESP8266 的部分

- 帧结构（68 / 长度 LE / 地址 / AFN / 数据 / CS / 16）与校验和算法（addr+AFN+data 模 256）——**完全一致**，已采用。
- 各功能码与数据域含义——**一致**，已采用。
- 学习/发射的时序逻辑（下发→等应答→等上报）——**一致**，已采用。

## 26. Arduino Nano 示例中必须为 ESP8266 重写的部分

- **串口**：Nano 用硬件 `Serial`（引脚 0/1、5V）；ESP8266 用 `SoftwareSerial`（D5/D6，3.3V），且 ESP8266 的
  USB `Serial` 用于调试日志（115200），二者不得混淆。
- **引脚**：Nano 示例引脚号不适用。当前工程接线：红外 RX/TX 用 D5/D6（GPIO14/12）；
  DHT11 数据脚用 D1（GPIO5）；均避开 GPIO6~11（Flash）与 D3/D4/D8（启动模式相关）。
- **电平**：Nano 为 5V 逻辑；ESP8266 为 3.3V，当前阶段模块也以 3.3V 供电，方向电平兼容（模块 TXD→ESP RX）。
- **供电**：不得因 .ino 示例或“5V 最佳”擅自给模块供 5V；当前阶段 3.3V。
- **框架**：示例为 Arduino API，ESP8266 用 PlatformIO + Arduino 框架，需自行实现非阻塞调度（`millis()`）与看门狗友好（`yield()`）。

## 27. Phase 3 只读 UART probe 实测确认（2026-07-15）

### 27.1 测试固件
- 独立构建环境 `[env:nodemcuv2_probe]`（platformio.ini），`build_flags = -DDISABLE_DHT`。
- DHT11 完全禁用：不实例化 Dht11、不调用读函数、`pinMode(DHT11_DATA_PIN, INPUT)` 置 DHT 引脚（D1/GPIO5）高阻；
  上电打印 `DHT11_DISABLED_FOR_IR_PROBE`。
- IR 仍用 D5(RX)/D6(TX) SoftwareSerial，懒初始化；`ir probe` / `ir info` 仅发只读查询帧。
- 编译/烧录：PASS（BUILD_DONE_EXIT=0；Hash of data verified）。COM6（CH9102，VID_1A86&PID_55D4）。

### 27.2 探测结果（IR_UART_PASS baud=115200）
- 优先 115200 一次成功，未触发其他波特率尝试。
- GET_BAUD 查询（AFN=04，无数据）：
  - 下发：`68 07 00 FF 04 03 16`  ← 与说明书 p.13 字节级一致
  - 回包：`68 08 00 00 04 04 08 16`
    - ADDR=00（模块自身地址，非 0xFF）✓
    - AFN=04 ✓
    - DATA=04（波特率索引 4 = 115200）✓
    - CS=(00+04+04)=0x08，与收到 0x08 一致 ✓
    - 帧尾 0x16 ✓
- GET_ADDR 查询（AFN=06，ir info）：
  - 下发：`68 07 00 FF 06 05 16`
  - 回包：`68 08 00 00 06 00 06 16` → 模块地址 = 0x00（默认）✓

### 27.4 运行态监测（要求 §五）
- ESP.getResetReason()：前后均为 `External System`（即烧录硬复位），probe 期间**无异常复位 / 看门狗复位**。
- Free Heap：前后均 51440（无泄漏）。

- 串口无乱码（回包为规则十六进制，解析全部 PASS）。

### 27.5 结论
- **接口类型**：TTL（帧结构 / 校验 / 应答全部符合说明书，非 485）。
- **实际波特率**：115200（模块出厂默认，索引 4）。
- **模块地址**：0x00（默认）。
- **协议栈实测可用**：查询类只读命令（GET_BAUD / GET_ADDR）在 115200 下稳定返回合法帧。
- **未建议改波特率**：模块已在最优 115200；且改波特率为持久化操作，须经用户明确授权。
  本次只读探测**不做任何写操作**（未发 SET_BAUD / SET_ADDR / LEARN / SEND / RESET / FORMAT）。
- 下一步 Phase 4（learn group 0）须再次获得用户明确授权，且需用户持遥控器对准模块黑色接收头。
