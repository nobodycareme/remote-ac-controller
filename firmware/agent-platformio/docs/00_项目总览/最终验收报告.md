## 1. 任务概述与执行纪律

本轮任务为**硬替换**校园网认证实现：将原先自制、未经上游验证的认证算法，完整替换为权威上游实现 `srun-c` v1.1.0，并完成端到端验证。任务以三条不可妥协的纪律约束全程：

- **不准保留两套并行认证算法**：删除自制实现，仅保留 vendored srun-c。
- **不准把编译通过等同于认证成功**：所有真实登录前的门禁（凭据 / TLS 固定 / 算法向量 / 参数）必须逐项通过，且真实登录本身必须有真实凭据。
- **不准在凭据加载或 TLS 校验不正确时提交真实账号密码**：无 `secrets.h` 时一律阻断，绝不伪造成功。

> **附：DHT11 集成基线（v0.3.1，仍然有效）**：DHT11 在 **D1/GPIO5 + Adafruit DHT 1.4.7** 上独立(30/30) + 主工程(133/133) 双重验证稳定，堆零泄漏、无复位；旧故障归因于自定义 `dht_service`/`rawTrace` 测试方法缺陷，非主机供电故障。本轮 srun-c 工作**未改动** DHT/IR 引脚与读取器，该基线结论继续成立。详见 `docs/05_故障排查/历史问题与结论修正.md` 与 `docs/00_项目总览/项目进度.md`。

## 4. 算法一致性验证（Phase 6）

`tools/verify_srun_vendor.py` 对 vendored 代码做三项校验，本次实跑输出：

```
SRUN_VENDOR_SHA_PASS
SRUN_ALGORITHM_VECTOR_PASS
OLD_AUTH_IMPLEMENTATION_EXCLUDED
OVERALL: ALL_GATES_PASS
```

- **SHA 一致性**：7 个文件与钉固提交逐字节一致；第 8 个（适配器）为预期偏离，单独标注。
- **规范 srun v2 符号齐全**：`hmac_md5_digest`、`x_encode`、`{SRBX1}`、srun 专用 Base64 字母表
  `LVoJPiCN2R8G90yg+hmFHuacZ1OWMnrsSTXkYpUq/3dlbfKwv6xztjI7DeBE45QA`、
  `CHALL_N="200"`、`CHALL_TYPE="1"`、`%7BMD5%7D`（运行期 `{MD5}`）。
- **固定参考向量（伪造输入）**：
  - `HMAC-MD5(pw, token)` hex = `fbee22162c04a4231b306960ec7c46a4`（32 字符）
  - `{SRBX1}` Base64 长度 = 135
  - `SHA1` chksum = `0fe294b698562efcf07044ab14dfddf7f6931dca`（40 字符）
  - 旧自制 `md5(md5(password)+token)` = `663aa0462681b66f0803de6fa875fa9d`（**确认 vendored 使用 HMAC-MD5，非旧算法**）
