# 校园网参数实证

> 本文件记录对西安电子科技大学（Xidian）校园网认证参数的实证结论，作为
> `src/network/campus_auth_vendor.cpp` 与 `include/config/campus_config.h` 的唯一权威依据。
> 早期自制实现的失败，部分源于参数（base_url 多带 `/index_8.html`、错误 `ac_id`、
> 误加运营商后缀）不正确；本文档以实测为准，杜绝猜参。
> 原始取证见 `docs/08_校园网接入/校园网门户取证.md`。

## 1. 权威参数表

| 参数 | 实测值 | 说明 |
| --- | --- | --- |
| SSID | `stu-xdwlan` | 学生无线接入点 |
| 门户主机 `CAMPUS_PORTAL_HOST` | `w.xidian.edu.cn` | 仅主机名，不含路径与协议 |
| `base_url` | `https://w.xidian.edu.cn` | **仅此**；**不得**追加 `/index_8.html` 等路径 |
| `ac_id` (`CAMPUS_AC_ID`) | `8` | 校区/接入控制器编号 |
| `domain` | 空（默认校园网） | 不传额外域 |
| 运营商后缀 | **禁止**（`@lt` / `@yd` / `@dx` 均不允许） | 账号即裸学工号，不加任何后缀 |
| ESP 本地 IP | 由真实 DHCP 分配 | 不得硬编码；`login()` 传入 `WiFi.localIP()` |
| 认证协议 | srun v2（深澜） | 由 vendored `srun-c` 实现 |

## 2. 关键纠正点（相对早期自制实现的失败根因）

1. **`base_url` 不含 `/index_8.html`**
   早期实现把门户首页路径拼进 `base_url`，导致 challenge/login 请求打到错误端点。
   正确做法：`base_url` 仅 `https://w.xidian.edu.cn`，路径由 `srun-c` 内部
   `/cgi-bin/get_challenge` 与 `/cgi-bin/srun_portal` 拼接。
2. **`ac_id=8` 且 `domain` 为空**
   错误 `ac_id` 会让服务端返回 `wrong ac_id` / `ip address not in the range`。
3. **禁止运营商后缀**
   `user@lt` / `user@yd` / `user@dx` 一律不允许；账号即 `CAMPUS_USERNAME` 原值。
4. **IP 来自真实 DHCP**
   登录请求中的 `ip` 字段必须是 ESP 实际获取到的本地地址，不能预置常量。

## 3. 配置落点

- 宏定义集中在 `include/config/campus_config.h`：
  ```cpp
  #define CAMPUS_SSID          "stu-xdwlan"
  #define CAMPUS_PORTAL_HOST   "w.xidian.edu.cn"
  #define CAMPUS_AC_ID         8
  // domain 为空（CAMPUS_DOMAIN 留空字符串），运算符后缀禁用
  ```
- `include/config/campus_tls_pin.h`：门户证书 SHA-1 指纹固定
  `F4:BD:59:32:8E:77:8C:CB:AD:6E:AE:85:86:59:36:FD:0D:28:47:F9`
  （`CN=*.xidian.edu.cn`，签发者 `GlobalSign RSA OV SSL CA 2018`，
  有效期 `2025-10-16` ~ `2026-11-17`）。该证书经 PC 可信 TLS 通道核验为真实证书，非代理 MITM。
- `include/config/campus_credentials.h`：仅经 `#if __has_include("secrets.h")` 加载
  `CAMPUS_USERNAME` / `CAMPUS_PASSWORD`；无 `secrets.h` 时为空，启动仅打印
  `CAMPUS_CREDS_READY=NO`，绝不打印账号/密码/ token / info / chksum / URL。

## 4. 认证门禁（未全部通过不得提交真实登录）

在 `nodemcuv2_campus_auth` 独立环境中，启动后依次校验：

1. `CAMPUS_CREDS_READY` 必须为 `YES`（否则 `AUTH_BLOCKED_NEEDS_LOCAL_CREDENTIALS`）。
2. `TLS_PIN_STATUS=VALID`（指纹已配置且能建立匹配 TLS，否则 `TLS_PIN_REQUIRED`）。
3. `SRUN_ALGORITHM_VECTOR_PASS`（算法向量与上游一致）。
4. `SSID=stu-xdwlan` / `DOMAIN=DEFAULT_CAMPUS` / `OPERATOR_SUFFIX=NONE` / `AC_ID=8`。

全部通过才允许 `campusLogin()` 发起真实 `get_challenge` + `srun_portal` 请求。

## 5. 结论

上述参数已作为单一事实来源写入固件配置；任何调试输出均不得回显凭据或拼接后的
完整登录 URL。认证是否真正成功，须由用户现场确认空调是否被远程唤醒，且须经过
Phase 9/10 受控真实登录 + 外部连通性三方验证。
