# 红外学习采集台 — ZJ-IR-V2

本地 Windows 红外交互式采集工具，作用于本仓库（路径由脚本自身位置推导，可用环境变量 `IR_PROJECT_ROOT` 覆盖）。

硬件链路：**NodeMCU ESP8266** →（UART）→ **ZJ-IR-V2 红外学习/回放模块**。
本工具仅通过 ESP8266 的串口 CLI 执行 `ir extlearn` 学习并读取**不透明外部红外波形**，
**绝不回放、绝不上云、绝不直接发向空调**。

> 优先级：**可靠采集 > 简单易用 > 完整元数据 > 美观**
> 本工具首版**不做**：波形绘图、协议破解、解码、网络服务、云端控制、自动回放、自动控制空调。

---

## 1. 如何启动

双击 `Firmware\Remote_AC_Controller\tools\start_ir_capture_studio.bat`。

启动器会：
1. 进入工程目录；
2. 优先使用系统 `py -3`，否则 `python`；
3. 检查 Python 是否存在；
4. 检查 `pyserial` 是否可导入；
5. 启动 `ir_capture_studio\app.py`；
6. 出错时保留窗口并 `pause`，**不会静默关闭**。

若提示缺少 `pyserial`，请运行：`python -m pip install pyserial`。

---

## 2. 如何连接设备

- 用 USB 连接 ESP8266（CH9102 芯片，VID=`1A86` PID=`55D4`）。
- 工具通过 `pyserial` 动态查找该 VID/PID，**不会硬编码 COM 端口**。
- 设备状态区显示：CH9102 是否连接、串口号、IR 波特率（模块为 **19200**）、模块状态。
- 多个匹配设备时会弹出选择框；零个匹配时显示“未发现 CH9102 设备”。
- 点击「重新扫描设备」可刷新。

> **并行开发期（另一工具正在占用串口时）**：本工具默认处于 `mock_only` 模拟模式，
> 不连接真机、不执行真实学习。必须由另一采集工具明确释放串口后，方可进行一次真机只读集成验证。

---

## 3. 如何填写状态

「空调完整状态（前态 / 后态）」网格逐字段记录：电源、模式、温度、风速、上下扫风、左右扫风、静音、强力、睡眠。

- **前态**：按遥控器按键**之前**空调/遥控器的完整状态。
- **后态**：预期按键**之后**的状态（例如开机任务：前态电源=关，后态电源=开）。
- 顶部还可填：品牌、空调型号、遥控器型号、任务类型、自定义名称、按下按键、备注、采集次数（1–20，默认 3）。

也可直接点「快捷预设」一键套用常用组合（仅填表单，不会自动开始）。

---

## 4. 如何创建任务

填好状态后，点击「**建立采集任务**」：

- 生成唯一会话目录 `References\IR\captures\studio\<session_id>\`；
- 重置计数：目标有效样本 = 采集次数，当前有效 = 0，总尝试 = 0，失败 = 0；
- 显示实际保存路径；
- **不会**自动进入学习态，也不会自动发送 `ir extlearn`。

---

## 5. 如何开始每次采集

每次采集都**必须手动点击「开始本次采集」**。点击前，工具**不会**发送学习命令、不会蜂鸣、不会等待红外数据。

点击后流程：
1. 禁用「开始本次采集」按钮（防重复点击）；
2. 记录点击时间，清空串口缓存与解析半帧；
3. 查询模块是否空闲；
4. 发送一次 `ir extlearn`；
5. 等待固件确认进入学习态（`IR_EXTLEARN_ENTER`）；
6. 立即蜂鸣（两声短蜂鸣提示可以按键）；
7. 大标签变红并显示：**现在按遥控器！只短按一次。**
8. 你直接按遥控器；
9. 工具自动接收、校验并保存；
10. 成功/失败后恢复「开始本次采集」按钮。

**下一次仍须再次手动点击，不会自动开始。**

---

## 6. 什么时候按遥控器

只有当大状态标签变为**红色「现在按遥控器！只短按一次。」**并听到蜂鸣后，才短按一次遥控器。
在「正在检查模块，请先不要按遥控器」（橙色）阶段**不要按**。

---

## 7. 数据保存在哪里

每个会话一个目录：

```
References\IR\captures\studio\<session_id>\
├── session.json
├── manifest.csv
├── <NAME>_001.bin
├── <NAME>_001.json
├── <NAME>_001.txt
├── <NAME>_001_serial.log
├── <NAME>_002.bin / .json / .txt / _serial.log
└── ...
```

- `.bin`：原始外部红外波形（不透明字节，不解码）；
- `.json`：完整元数据（状态前/后、按键、校验、计时、SHA256 等）；
- `.txt`：人类可读摘要；
- `_serial.log`：本次采集的串口原始行；
- `manifest.csv`：会话级样本清单。

若会话目录已存在，自动加 `_02`、`_03` 安全后缀，**绝不覆盖**已有会话。

---

## 8. 失败后如何重试

失败类型包括：串口未找到、串口被占用、模块忙碌、学习命令未确认、等待遥控超时、帧头/长度/校验失败、取消等。

失败时：
- 仅保存失败 `JSON` + 串口日志，**不生成伪成功 BIN**；
- 失败次数 +1（不计入有效样本）；
- 大标签显示红色失败原因；
- 你可点击「开始本次采集」**重试当前样本**，或调整状态后继续，或点「安全退出」。

**不会自动无限重试。**

---

## 9. 如何安全退出

- 点「**安全退出**」：停止新任务、等待当前写操作结束、关闭串口、释放互斥锁、保存会话状态；
- 「**取消等待**」：尚未发送学习命令时直接取消；已进入学习态则等待模块安全退出；
- 关闭窗口等同于安全退出（已挂钩 `WM_DELETE_WINDOW`）；
- 退出过程**不执行任何回放**。

---

## 10. 本工具不会回放红外

代码内置硬门禁：

```python
ALLOW_IR_REPLAY = False
ALLOW_CLOUD_IR  = False
```

命令白名单仅允许：`ir info` / `ir extlearn` / `status`。
任何 `ir send`、`ir extsend`、回放、发射、云端类命令都会被拒绝并阻断。

## 目录结构

```
tools\ir_capture_studio\
├── app.py                  # 主窗口与采集编排
├── capture_core_adapter.py # 后端抽象 + 协议解析（复用 capture_repeat 算法）
├── models.py               # 数据模型、命名、默认值、预设
├── storage.py              # 落盘：BIN/JSON/TXT/log/manifest/session
├── serial_device.py        # 真实 CH9102 设备 + 两级锁保护
├── mock_device.py          # 模拟设备（并行开发期）
├── widgets.py              # 复用 UI 组件
├── user_settings.json      # 上次表单（非敏感）
├── tests\                  # 模拟测试
└── README.md
```

## 并行开发纪律

- 独占目录 `tools\ir_capture_studio\`，不修改另一 Agent 的文件；
- 10 次固定采集工具释放串口前，本工具为 `mock_only`，不连真机；
- 真机只读验证须在其释放串口后，由用户允许才进行一次。
